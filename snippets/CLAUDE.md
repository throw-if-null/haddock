## Documentation maintenance

Use the `doc-style` skill whenever you change code, and before you write or edit
documentation, comments, docstrings, commit messages, or pull request descriptions. The
skill holds the full rules. In summary:

- After a code change, review the comments and documents that describe the changed code.
  Update or delete what the change made wrong or redundant.
- Edit, consolidate, or delete existing prose before you add more. State each fact in one
  place.
- Describe the current system. Commit messages and changelogs hold the change history.
- Write a comment only for information that the code does not show.
- Keep every constraint, qualification, and warning that is still true.
- Do not edit documentation that the change does not affect.
